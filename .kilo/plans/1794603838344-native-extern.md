# Native `@extern` with Required C Signatures

## Goal

Replace the legacy name-only `@extern Name;` form with a native-only declaration that carries a complete C signature:

```lls
pub @extern "c" @func puts(s: cstring): i32;
```

The declaration must be sufficient to typecheck calls, emit a Zig `extern fn`, and link against libc or another C object without any runtime lookup or VM support.

Scope:

- native backend only; the VM is being retired
- full signatures with parameter names and types
- `cstring` and `?cstring`
- scalar types, `*T`, and `?*T`
- C variadic functions with `...`
- `pub` exports through LLTS modules
- clear rejection of data symbols, unsupported ABIs, and unsupported parameter types

Explicitly out of scope for this change:

- extern data symbols (parse and reject)
- non-C ABIs (`"stdcall"`, `"sysv"`, `"win64"`, `"zig"`, ...)
- symbol aliasing (`source as "link-name"`)
- extern structs passed by value or C layout modeling
- dynamic `string` to `cstring` conversion
- custom link libraries and extra linker flags
- VM/bytecode extern support
- validating `printf`-style format strings

## Decisions

- **Syntax:** `pub @extern "c" @func puts(s: cstring): i32;`
- **ABI:** required string; only `"c"` is accepted in v1.
- **Function marker:** `@func` is required for function declarations.
- **Signatures:** parameter names and types are mandatory, even outside `--strict`.
- **Data form:** `@extern "c" errno: i32;` parses, then fails with "extern data symbols are not supported yet".
- **Legacy form:** `@extern Name;` is a parse error with a migration hint.
- **Variadics:** `...` is supported as the final token of an extern parameter list; at least one fixed parameter is required.
- **Pointers:** `*T` and `?*T` are supported when `T` is an allowed scalar. `?*Struct` is rejected.
- **C strings:** `cstring` maps to a NUL-terminated `char*`; `?cstring` maps to a nullable one. Only string literals and other cstring values convert to `cstring` in v1.
- **Linking:** libc is already linked by the native pipeline (`-lc`); no linker changes are required.
- **VM:** any VM attempt to compile an extern declaration reports "extern is native-only".
- **Symbols:** the LLTS source name and the link symbol are the same in v1. Module qualification changes only the source name.

## Syntax

```lls
pub @extern "c" @func puts(s: cstring): i32;
@extern "c" @func getpid(): i32;
@extern "c" @func strlen(s: cstring): usize;
@extern "c" @func getenv(name: cstring): ?cstring;
@extern "c" @func malloc(size: usize): ?*u8;
@extern "c" @func free(ptr: ?*u8): void;
@extern "c" @func write(fd: i32, buf: *u8, count: usize): isize;
@extern "c" @func printf(fmt: cstring, ...): i32;
```

Grammar:

```ebnf
ExternDecl   ::= ( "pub" )? "@extern" STRING ExternItem
ExternItem   ::= "@func" IDENTIFIER "(" ExternParams? ")" ( ":" Type )? ";"
               | IDENTIFIER ":" Type ";"
ExternParams ::= ExternParam ( "," ExternParam )* ( "," "..." )?
ExternParam  ::= IDENTIFIER ":" Type
```

Rules:

- `@extern` is file-scope only. A nested declaration is a parse error.
- A body is forbidden.
- Return type omitted means `void`.
- A bare `...` is only valid in an extern parameter list and only at the end.
- No parameter may follow `...`.
- Data declarations parse so tooling can see them, but `registerExterns` rejects them.
- `pub` keeps its existing module-export semantics. The link symbol is never qualified.

## Type Model

| LLTS spelling | IR representation | Emitted Zig |
| --- | --- | --- |
| `i8` .. `i64`, `u8` .. `u64`, `isize`, `usize` | existing scalar | same |
| `f32`, `f64` | existing scalar | same |
| `void` | `ir.TVoid` | `void` |
| `cstring` | new `ir.Type.cstring` | `[*:0]const u8` |
| `?cstring` | `union(cstring, null)` | `?[*:0]const u8` |
| `*T` | `ir.ptr` | `*T` |
| `?*T` | `union(ptr(T), null)` | `?*T` |

`cstring` is a first-class type, but its supported operations are deliberately narrow:

- assign from a string literal, another `cstring`, or `null` when optional
- pass to extern parameters and variadic arguments
- optional unwrap, null comparison, and `@if` on `?cstring`
- no `len`, slicing, arithmetic, or printing in v1

`*u8` is the raw byte-buffer pointer. Extern argument emission accepts these sources for a `*u8` parameter:

- a string literal (emitted with `@constCast`, must not be written by C)
- a `string`/`[]const u8` value (emitted with `@constCast(ptr)`)
- a `[]u8` slice (emitted as `.ptr`)
- an `[N]u8` array (emitted as a pointer to its first element)

`?*u8` additionally accepts `null` and `*u8`.

### C variadic promotion

Zig does not perform C default argument promotions. LLTS must do them at the extern call site:

| Trailing LLTS argument | Emitted C argument type |
| --- | --- |
| untyped integer literal | `i32` |
| `i8`, `i16`, `u8`, `u16` | `i32` |
| `i32` / `u32` | `i32` / `u32` |
| `i64`, `u64`, `isize`, `usize` | unchanged |
| `f32` | `f64` |
| `f64` | `f64` |
| `bool` | `i32` via `@intFromBool` |
| `cstring`, `?cstring` | unchanged |
| string literal | `[*:0]const u8` |
| `*T`, `?*T` | unchanged |
| `null` | `@as(?*anyopaque, null)` |

Rejected as variadic arguments:

- runtime `string` / `[]const u8` values (not NUL-terminated)
- arrays, slices, structs, unions, error values, function values
- `?T` for any payload other than a pointer or cstring

`printf("%d", 42)` emits `printf(..., @as(i32, 42))`. `printf("%ld", x)` requires `x: i64`. Format strings are not validated.

## Architecture

### 1. AST

Extend the extern declaration in `src/ast/stmt.zig`:

```zig
pub const ExternKind = enum { func, data };

pub const Extern = struct {
    name: []const u8,        // source name; module-qualified later
    symbol: []const u8,      // untouched link symbol
    abi: []const u8,         // "c"
    kind: ExternKind,
    params: []Param,         // full signatures, names required
    return_type: ?*Node,     // null = void
    data_type: ?*Node,       // set only for the rejected data form
    is_c_variadic: bool,
    is_public: bool,
    loc: Location,
};
```

- Set `symbol = name` in the parser before modules qualify `name`.
- Deep-clone params, return type, and data type in `src/ast/clone.zig`.
- `src/compiler/modules.zig` already qualifies `.extern_decl` names and records `pub` exports; leave `symbol` alone.

### 2. Parser

In `src/parser/decl.zig`:

- Replace `parseCompilerExtern` (`src/parser/decl.zig:73`).
- Add a dedicated `parseExternParams`; do not reuse `parseParamsList`, because the latter treats `...` as a named rest parameter.
- Parse `@extern STRING`, then either `@func` or the data form.
- Require `:` before every parameter type and after the data name.
- Add a parser `block_depth` counter (increment/decrement around block parsing) and reject `@extern` when `block_depth != 0`.
- Use the existing diagnostic helpers so LSP still receives partial ASTs.

### 3. IR and type resolution

In `src/compiler/typecheck/ir.zig`:

- `namedType`/`isBuiltinTypeName` recognize `cstring`.

In `src/compiler/typecheck/from_ast.zig`:

In `src/compiler/state.zig`:

```zig
    symbol: []const u8,        // link symbol

    is_public: bool,

```

Add:

- `externs: std.StringHashMap(ExternInfo)`
- `extern_calls: std.AutoHashMap(*ast.Node, []const u8)`

Initialize/deinit both in `CompilerState`.

In `src/compiler/root.zig`:

- Add `registerExterns` after `resolveImports`/`registerModuleDecls` in both `analyze` and `prepareForTypecheck`.
- Validate:
  - `abi == "c"`
  - function form only (data form reports the reserved-symbol error)
  - at least one fixed parameter when `is_c_variadic`
  - unique parameter names
  - allowed C types only
  - no conflict with functions, globals, builtins, or another extern
  - link symbol `main` is rejected (it would collide with the generated entry point)
- Store `source_name` as the qualified name and `symbol` as the original name.
- Do not put externs in `state.native_globals`; keep that map for runtime builtins.

Replace `compileExtern` in `src/compiler/stmt/decl.zig:345`:

- No longer add the name to `native_globals`.
- If reached through the VM statement path, report "extern declarations are native-only".
- Nested declarations were already rejected by the parser.

### 5. Typechecking

In `src/compiler/typecheck/root.zig`:

- In `inferCall`, after `resolveCalleeName` and before generic/template handling, check `state.externs`.
- Record `extern_calls.put(call_node, qualified_name)`.
- Check fixed arguments against `CType`:
  - scalar: existing `requireAssignFrom`
  - `cstring`: string literal or `cstring`
  - `?cstring`: string literal, `cstring`, or `null`
  - `*T`: matching pointer, or a byte-sequence source when `T == u8`
  - `?*T`: the `*T` cases plus `null`
- Check arity:
  - non-variadic: exact fixed count
  - variadic: at least the fixed count
- Check trailing args against the variadic whitelist and reject runtime `string` values.
- Return the extern's IR return type (`void`, scalar, cstring, or optional cstring).
- Reject extern identifiers used as ordinary values. Add the check in `inferPrimaryExpr` so `print(puts)`, `$f = puts`, `@typeOf(puts)`, and `@nameOf(puts)` fail with "extern function 'puts' can only be called directly".
- Add cstring assignability/coercion rules to `requireAssignFrom`:
  - `cstring` accepts only `cstring` or a string literal
  - `?cstring` accepts `cstring`, `null`, or a string literal
  - `cstring` does not implicitly become `string` or `*u8`
- Keep format-string validation out of scope.

### 7. Native emitter: declarations

In `src/compiler/codegen/emitter/root.zig`:

- Add `emitExternDecls` to the `Emitter.emit` pipeline after globals and before functions.
- Iterate `state.externs`, sorted deterministically.
- Deduplicate by link symbol. If the same symbol is declared twice with different signatures, report a compile error; identical duplicates emit once.
- Emit:
  ```zig
  extern fn puts(s: [*:0]const u8) i32;
  extern fn printf(fmt: [*:0]const u8, ...) i32;
  extern fn malloc(size: usize) ?*u8;
  ```
- Quote Zig-keyword symbols with `@"..."`.
- Map `CType` through a single helper so declarations and call coercions cannot drift.

`valTypeFromIR` maps `.cstring` to:

```zig
ValType{
    .display = "cstring",
    .clean = "cstring",
    .kind = .pointer,
    .zig = "[*:0]const u8",
    .payload = &u8,
}
```

Optional cstring then flows through the existing optional wrapping and becomes `?[*:0]const u8`.

### 8. Native emitter: calls

In `src/compiler/codegen/emitter/expr.zig`:

- At the top of `emitCall`, before member/unresolved-function paths, check `state.extern_calls.get(node)`.
- Emit a direct call with no `ctx` and no `try`:
  ```zig
  puts("hello")
  ```
- Fixed arguments use `emitExternArg(arg, ctype)`:
  - scalar: `emitValueCoerced`/`emitStrongCoercion` to the exact C type
  - `cstring`: string literal or cstring expression as-is
  - `?cstring`: literal/cstring/null as-is
  - `*T`: matching pointer as-is; byte-buffer sources use the rules in "Type Model"
  - `?*T`: same plus `null`
- Variadic arguments use `emitCVararg(arg)`:
  - apply the promotion table explicitly
  - use `emitStrongCoercion` for integer/float literals so Zig sees a concrete type
  - emit `@as(i32, @intFromBool(x))` for `bool`
  - emit `@as(?*anyopaque, null)` for `null`
  - reject anything the typechecker should not have allowed, with an emitter diagnostic
- `void` extern calls work as expression statements through the existing `emitExprStatement` path (`puts(...);`).
- Externs remain non-values; no closure or function-pointer path is added.

## Risks / Constraints

- **C default promotions are the highest-risk detail.** Zig does not promote `f32` to `f64` or small integers to `i32` for variadic calls. The emitter must do it explicitly; otherwise `printf` silently reads the wrong bytes.
- `i32` is assumed to be C `int` on supported native targets. Document the mapping; do not silently accept `string` where `cstring` is required.
- Passing a string literal or `string` to `*u8` requires a const cast. This is ABI-correct but unsafe if C writes to the buffer; document it and prefer `[]u8`/`[N]u8` for writable buffers.
- Do not confuse `cstring` with LLTS `string`. A runtime `string` is length-prefixed and may not be NUL-terminated, so dynamic conversion is rejected in v1.
- Preserve module qualification for source names while keeping `symbol` bare. A qualified link symbol would fail at link time.
- Deduplicate extern declarations by link symbol and reject conflicting signatures; otherwise emitted Zig has duplicate or conflicting declarations.
- Reject symbol `main` and Zig-keyword symbols must be quoted.
- Keep the tree-sitter `extern_declaration` name and `name` field stable to avoid breaking the VSCode extension.
- `?*T` is only for scalar pointees. Extern structs and pointer-to-pointer are future work.
- Variadic format strings are unchecked; a wrong `%d`/`%ld` type is the caller's responsibility.
- Do not add extern support to the VM or `native_globals`.
- Existing single-error diagnostics and test fixtures must keep their current formatting.
