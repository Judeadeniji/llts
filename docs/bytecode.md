# LLTS Bytecode Architecture

This document provides a technical overview of the bytecode format, runtime values, and instruction set used by the LLTS-zig virtual machine. The architecture is designed to execute a flat sequence of instructions generated by the compiler.

## 1. Chunk Architecture (`chunk.zig`)

A `Chunk` represents a compiled unit of code. It contains the executable bytecode alongside its associated data pools (constants, strings, functions, etc.).

### Key Components

*   **`code: std.ArrayList(u8)`**: The linear array of bytecode instructions and their immediate operands.
*   **`constants: std.ArrayList(Value)`**: A pool of runtime values loaded via constant indices. It is limited to 65536 constants (addressed via `u16`).
*   **`strings: std.ArrayList([]const u8)`**: Parallel string storage for interned strings (e.g., variable and property names).
*   **`functions: std.StringHashMap(LltsFunction)`**: A map of declared functions within the chunk.
*   **`exports: std.StringHashMap(void)`**: A map tracking exported module symbols.

### Operations

*   `write(byte: u8)` / `writeOp(op: OpCode)`: Appends an instruction or raw byte to the chunk.
*   `addConstant(v: Value) -> u16`: Registers a constant and returns its 16-bit index.
*   `addStringConstant(s: []const u8) -> u16`: Interns a string and stores it as a `.name` Value in the constants pool, deduplicating if it already exists.

## 2. Runtime Values (`value.zig`)

The VM operates on a tagged union, `Value`, which can represent various primitive and reference types. 

### Value Types

*   **Primitives**: 
    *   `null`: Represents absence of value.
    *   `bool`: Boolean (`true` or `false`).
    *   `int`: 32-bit signed integer (`i32`).
    *   `float`: 64-bit floating point (`f64`).
*   **Heap/References**: 
    *   `ptr: i32`: A pointer into a separate `i32` heap, representing arrays, strings, errors, and struct instances.
*   **Strings & Identifiers**:
    *   `name: u32`: An interned name index pointing into the chunk's `strings` table (used for globals and properties).
    *   `slice: { offset: u32, len: u32 }`: A string view pointing into the VM's global `string_bytes` buffer.
*   **Execution Entities**:
    *   `function: LltsFunction`: A user-defined LLTS function.
    *   `native: *const NativeFunction`: A binding to a Zig native function.
    *   `module: *ModuleObject`: A module object created by imports, containing a hash map of dynamic properties.

### Truthiness

A `Value` evaluates to true in conditional jumps (`isTruthy`) under the following conditions:
*   Booleans: If explicitly `true`.
*   Numbers (`int`, `float`): If non-zero.
*   `slice`: If length > 0.
*   `ptr`, `native`, `function`, `name`, `module`: Always `true`.
*   `null`: Always `false`.

## 3. Instruction Set (`opcode.zig`)

The `OpCode` enum defines the operations executed by the VM. These are represented as 8-bit unsigned integers (`u8`). Numeric values are designed to map precisely to the TypeScript prototype.

### Core Categories

#### Stack & Constant Loading
*   `OP_CONSTANT`: Load a value from the constant pool.
*   `OP_NULL`, `OP_TRUE`, `OP_FALSE`: Push primitive literals.
*   `OP_DUP`, `OP_POP`: Stack manipulation.

#### Arithmetic & String Ops
*   `OP_ADD`, `OP_SUB`, `OP_MUL`, `OP_DIV`, `OP_MOD`, `OP_POW`: Standard mathematical operations.
*   `OP_STRING_ADD`: String concatenation.
*   `OP_NEGATE`: Unary minus.

#### Logic & Comparison
*   `OP_EQUAL`, `OP_NOT_EQUAL`: Value equality.
*   `OP_STRING_EQUAL`, `OP_STRING_NOT_EQUAL`: String specific equality.
*   `OP_LESS`, `OP_LESS_EQUAL`, `OP_GREATER`, `OP_GREATER_EQUAL`: Numeric comparison.
*   `OP_NOT`: Unary logical negation.

#### Variable & Property Access
*   `OP_GET_GLOBAL`, `OP_SET_GLOBAL`: Global variable access.
*   `OP_GET_LOCAL`, `OP_SET_LOCAL`: Local variable access (usually relative to the stack frame).
*   `OP_GET_PROPERTY`, `OP_SET_PROPERTY`: Object property access.
*   `OP_GET_INDEX`, `OP_SET_INDEX`: Dynamic property / array index access.

#### Data Structures
*   `OP_GET_ARRAY`, `OP_SET_ARRAY`: Direct array operations.
*   `OP_MAKE_STRING`, `OP_MAKE_ERROR`, `OP_IS_ERROR`: Object creation and type checking.

#### Control Flow & Functions
*   `OP_JUMP`: Unconditional jump.
*   `OP_JUMP_IF_FALSE`: Conditional branch (pops condition, jumps if falsy).
*   `OP_LOOP`: Backwards jump.
*   `OP_CALL`, `OP_CALL_STATIC`: Function invocation.
*   `OP_RETURN`: Return from function.

#### Modules & Miscellaneous
*   `OP_IMPORT`: Import an external module.
*   `OP_GET_MODULE`: Fetch a loaded module object.
*   `OP_GET_FUNCTION`: Retrieve a function.
*   `OP_PACK_REST`: Variadic arguments packing.
*   `OP_PRINT`: Output value.
*   `OP_LINE`, `OP_MARK_CONST`, `OP_ASSERT_TYPE`: Tooling and debugging hooks.

## 4. Execution Format

1. **Compilation**: The compiler emits a sequence of `u8` opcodes into `Chunk.code`. 
2. **Operands**: Instructions that require operands (like `OP_CONSTANT` or `OP_JUMP`) expect their arguments to be serialized immediately after the opcode in `Chunk.code`. For instance, `OP_CONSTANT` is followed by a 16-bit constant index.
3. **Execution**: The VM maintains an Instruction Pointer (`ip`) scanning through the chunk. It fetches the opcode, decodes any immediate operands, manipulates the execution stack using `Value` tagged unions, and advances `ip`.
