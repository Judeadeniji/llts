# llts-zig Parser Documentation

This document describes the design, architecture, and behavior of the `parser` component in the `llts-zig` compiler (located in `src/parser`). It is designed for agents seeking to understand the grammar rules, AST generation, and constraints of the language.

## Overview

The parser transforms an array of `Token`s generated by the scanner into an Abstract Syntax Tree (AST), represented by `ast.Node`s. It's a hand-written recursive descent parser with Pratt parsing for binary expressions. The parser explicitly uses an `ArenaAllocator` bound to the generated `Document`, simplifying memory management.

### Entry Point
- `root.zig` exposes `parse(allocator, tokens, path, source)`. It initializes a `Document` with an `ArenaAllocator` and calls `stmt.parseStatement` iteratively to produce the AST.
- State is carried using the `Parser` struct defined in `ctx.zig`, which tracks the `tokens`, `current` index, and offers lookahead/matching utilities (`peek`, `check`, `match`, `consume`, `advance`).

## Architecture & Data Flow

### Context and Error Handling (`ctx.zig`)
- Provides precise error recovery integrated with `errors/report.zig` and the `errors/diag.zig` diagnostic tracking system.
- Provides utilities like `failTok` and `failMsg` to gracefully halt parsing and print rich, context-aware compiler diagnostics.
- Leverages the robust IO subsystem (`src/io/`) for POSIX-compliant writes and ANSI coloring, while avoiding duplicate CLI errors via `diag.zig`.
- `rejectRegisterSigil` handles the restriction that `$registers` can only be used in assignments (declarations); using a `$` prefixed identifier in normal expression contexts will yield a syntax error.

### Declarations (`decl.zig`)
- **Registers**: Standard variable assignments are treated as declarations. Parsed as `$Name = value` or `$Name: Type = value`.
- **Compiler Directives**: Keywords prefixed with `@` (e.g., `@const`, `@import`, `@func`, `@extern`) delegate to specialized parsing paths.
  - **Functions**: `@func name(a, b: Type, ...) { ... }`. Parameters are parsed as pseudo-declarations with literal `0` as the initial value. Variadic parameters (`...`) are verified to be the last parameter.
  - **Externs**: `@extern Name;` allows linking to external elements.
  - **Imports**: `@import("path");` evaluates imports.

### Statements (`stmt.zig`)
- Routes tokens to declarations, expression statements, or control flow components.
- Handles labeled statements: `labelName: statement` is passed down to control structures (blocks, `@for`, `@if`, `@switch`) using `applyLabel`.
- Supports visibility modifiers: `pub @func...` marks the resulting AST node's `is_public` flag.

### Expressions (`expr.zig`)
- **Assignments**: Right-associative assignment expressions (`left = right`).
- **Binary & Unary Ops**: Implements a Pratt parser for binary operations (via precedence defined in `shared/precedence.zig`). Supports prefix unary expressions (e.g., `-`, `+`).
- **Postfix Ops**: 
  - Function calls: `foo()`
  - Field access: `foo.bar`
  - Array indexing: `foo[expr]`
  - Try operator: `expr?` (returns `.try_expr` node)
  - Struct initialization: Following a primary or member node, `{ field: val }` initializes a struct (`.struct_init`).
- **Literals**: Reifies booleans, strings, hex, binary, octal, numbers, and the special keyword `null`. Error variants are parsed as `error(message)`.

### Control Flow (`control.zig`)
All control constructs are built as expressions.
- **Blocks**: Standard `{ ... }` curly-brace blocks.
- **`@if`**: `@if (cond) |capture| { ... } @else { ... }`. Supports optional captures and chaining (`@else @if`).
- **`@for`**: Maps `for` loops into 3 kinds based on captures and conditions:
  - Range: `@for (0..N) |cap| { ... }` (Note: C-style `for` is explicitly rejected).
  - Condition: `@for (cond) { ... }`
  - Iterable: `@for (iterable) |cap| { ... }`
- **`@switch`**: `@switch (cond) { pat1, pat2 => { ... }, @else => { ... } }`. Note that no further prongs are allowed after the `@else` prong.
- **Jump statements**: `return [expr];`, `break [:label] [expr];`, `continue [:label];`, `defer { ... }` (or `defer expr;`).

### Structs & Enums (`structs.zig`, `enums.zig`)
- **`@struct Name`**: Fields are parsed as `name: Type;` (semi-colon required). Methods inside a struct defined with `@func methodName(...) { ... }` are mangled to `Name::methodName` for the AST.
- **`@enum Name`**: Parsed as a comma-separated list of variants enclosed in `{ ... }`.

### Type System Annotations (`types.zig`)
- **Type Arrays**: Parsed as `[N]T` (where `N` can be base-10, hex, binary, or octal) or `[]T` for dynamic length.
- **Unions**: Parses piped types `T | U`.
- **Primitives**: Standard identifiers and the `error` keyword.

## Important Constraints & Rules
- **Sigil Usage**: `$` is only for LHS declarations (`$reg = 1`). RHS usages must drop the sigil (`x = reg`).
- **Labels**: Can only be applied to blocks, `@for`, `@if`, and `@switch`.
- **Struct Parsing**: When defining structs, fields must end in `;`. Trailing commas aren't used for struct definitions. Struct instantiation uses `,` to separate fields.
- **Variadic Arguments**: Represented by `...` and must strict be the last parameter in an `@func` definition.
- **Error Types**: The `error` keyword can be used both as a literal expression (`error("msg")`) and as a type (`error | int`).
